# Lsearch Spec 005 — V2：Qt5 GUI

Status: **Done**（主界面/托盘/索引管理页/打包集成均完成；麒麟实机安装待验证）

## Why
终端前端（CLI/TUI）已就绪；麒麟桌面是 UKUI（Qt 系），桌面用户需要图形界面以获得
Everything 级别的视觉体验（实时搜索框 + 结果表格 + 托盘）。由于 `core` 与 `ipc`
已完全解耦，GUI 只需新增一个前端，复用现有 IPC client，无需改动索引/守护进程。

## What Changes（预期）
- 新增 `gui/`（Qt5 Widgets），复用 `liblsearch_ipc` 访问 `lsearchd`
- 主窗口：顶部实时搜索框、结果表格（名称/路径/大小/修改时间，可点击表头排序）、
  状态栏（索引统计 + 重建）；双击/右键"打开文件 / 打开所在目录"（xdg-open）
- 系统托盘：图标 + 菜单（显示、搜索、重建、退出），支持唤出
- 索引管理页：查看/增删根路径、一键重建、显示索引规模

## Requirements（草案）

#### R1 — 复用现有后端
GUI 不直接接触 `core/indexer|watcher|db`，仅通过 `ipc/client` 通信；守护进程未启动时
沿用自动拉起逻辑。

#### R2 — 实时搜索
输入即搜（结果随键入即时刷新），保持 Everything 手感；排序/过滤与 CLI 对齐
（name/path/size/mtime、目录/文件过滤）。

#### R3 — 打开与托盘
双击打开文件、右键"打开所在目录"；托盘常驻，关闭窗口不退出守护进程。

#### R4 — 多架构 UI 构建
Qt5 依赖纳入 CMake（`find_package(Qt5 Widgets)`），随 deb/rpm 打包；麒麟环境预装 Qt5。

## Scenario（草案）
Given 守护进程已建索引（或 GUI 自动拉起）
When 用户在搜索框输入关键词
Then 结果表随输入即时刷新，命中子串可高亮
When 双击某结果
Then 用系统默认程序打开；右键可"打开所在目录"
When 关闭窗口
Then 进程驻留托盘，索引与 inotify 持续可用
